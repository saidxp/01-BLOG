# Database Design Specification

## Overview

This document defines the database structure for the Social Block Platform.

The platform allows users to:

* Publish posts
* Subscribe to other users
* Receive notifications 
* Interact through likes and comments
* Report inappropriate content
* Be moderated by administrators

---

# Users

## Purpose

Stores user authentication, profile information, and account status.

## Columns

| Column            | Type      | Description            |
| ----------------- | --------- | ---------------------- |
| id                | UUID      | Primary Key            |
| username          | VARCHAR   | Unique username        |
| email             | VARCHAR   | Unique email address   |
| password_hash     | VARCHAR   | Encrypted password     |
| role              | ENUM      | USER or ADMIN          |
| status            | ENUM      | ACTIVE or BANNED       |
| bio               | TEXT      | User biography         |
| profile_image_url | VARCHAR   | Profile image location |
| created_at        | TIMESTAMP | Account creation date  |
| updated_at        | TIMESTAMP | Last update date       |

---

# Subscriptions

## Purpose

Stores relationships between users who subscribe to other users.

## Columns

* id
* subscriber_id
* target_user_id
* created_at

## Constraints

* A user cannot subscribe to themselves.
* A subscription pair must be unique.

---

# Posts

## Purpose

Stores user-generated content.

## Columns

* id
* user_id
* description
* status
* created_at
* updated_at

## Status Values

* ACTIVE
* HIDDEN
* DELETED

---

# Media

## Purpose

Stores images and videos attached to posts.

## Columns

* id
* post_id
* media_type
* storage_path
* preview_path
* created_at

## Media Types

* IMAGE
* VIDEO

---

# Likes

## Purpose

Stores post likes.

## Columns

* id
* user_id
* post_id
* created_at

## Constraints

One user can like a post only once.

---

# Comments

## Purpose

Stores comments posted by users.

## Columns

* id
* post_id
* user_id
* content
* created_at
* updated_at

---

# Notifications

## Purpose

Stores user notifications generated by system events.

## Columns

* id
* user_id
* type
* reference_id
* message
* is_read
* created_at

## Notification Types

* NEW_POST
* REPORT_RESOLVED
* ADMIN_ACTION

---

# Reports

## Purpose

Stores reports submitted against users.

## Columns

* id
* reporter_id
* reported_user_id
* reason
* status
* created_at

## Status Values

* PENDING
* REVIEWED
* RESOLVED
* REJECTED

---

# Admin Actions

## Purpose

Maintains a moderation audit trail.

## Columns

* id
* admin_id
* action_type
* target_type
* target_id
* created_at

## Example Actions

* BAN_USER
* DELETE_POST
* REMOVE_POST
* RESOLVE_REPORT
